POSTDevice
Verify a device and get an access token
/device/verify/

The device sends its ID and secret to prove who it is. If valid, the server gives back a fresh access token that must be used in all future requests.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredThe unique ID assigned to your device
device_secretstringRequiredThe secret password set for your device
Example Request
{ "device_id": "esp32-001", "device_secret": "my-secret-key" }
Responses
Success
Wrong credentials
{ "success": true, "message": "Device verified successfully", "access_token": "a3f9b2c1..." }
{ "success": false, "message": "Invalid device credentials" }
ⓘSave the access_token you receive. You'll need it in the headers of every other request.
POSTDevice
Send sensor / telemetry data
/device/telemetry/

Send any sensor readings or measurements from your device. The telemetry field can hold any key-value pairs you want to log.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredYour device's ID
access_tokenstringRequiredToken from Device Verify
telemetryobjectRequiredA JSON object of any sensor readings
Example Request
{
  "device_id": "esp32-001",
  "access_token": "a3f9b2c1...",
  "telemetry": {
    "temperature": 28.5,
    "humidity": 65,
    "pressure": 1013
  }
}
Responses
Success (201)
Unauthorized (401)
{ "success": true, "message": "Telemetry stored successfully" }
{ "success": false, "message": "Invalid device credentials" }
POSTDevice
Send a heartbeat (keep-alive ping)
/device/heartbeat/

Call this on a regular interval to tell the server your device is still alive. It updates the device's current status and how long it has been running.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredYour device's ID
access_tokenstringRequiredToken from Device Verify
statusstringRequiredCurrent device state — see valid values below
uptimeintegerRequiredSeconds since last boot
Valid Status Values
online
Working normally
offline
Not reachable
error
Non-critical fault
warning
Needs attention
critical
Severe issue
unknown
State unclear
Example Request
{
  "device_id": "esp32-001",
  "access_token": "a3f9b2c1...",
  "status": "online",
  "uptime": 3600
}
Response
{ "success": true, "message": "Heartbeat received successfully" }
POSTDevice
Report device health metrics
/device/health/

Send hardware-level stats like CPU load, memory, temperature, and battery. All metric fields are optional — only send what your device can measure.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredYour device's ID
access_tokenstringRequiredToken from Device Verify
cpu_usagefloatOptionalCPU usage as a percentage (0–100)
memory_usagefloatOptionalRAM usage as a percentage (0–100)
storage_usagefloatOptionalStorage usage as a percentage (0–100)
temperaturefloatOptionalDevice temperature in °C
battery_percentageintegerOptionalBattery level (0–100)
rssiintegerOptionalWi-Fi signal strength in dBm (e.g. -65)
Example Request
{
  "device_id": "esp32-001",
  "access_token": "a3f9b2c1...",
  "cpu_usage": 42.5,
  "memory_usage": 58.0,
  "temperature": 38.2,
  "rssi": -68
}
Response
{ "success": true, "message": "Device health logs stored successfully" }
POSTDashboard
Send a command to a device
/device/commands-create/

Queue a command for a device to execute. Send a single command or a list of multiple commands at once.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredID of the target device
commandstringOne of theseA single command string, e.g. reboot
multicommandsarrayOne of theseA list of commands to run in sequence
payloadobjectOptionalExtra data to pass along with a single command
Single Command
{
  "device_id": "esp32-001",
  "command": "reboot",
  "payload": { "delay_seconds": 5 }
}
Multiple Commands
{
  "device_id": "esp32-001",
  "multicommands": ["set_led_red", "play_alert", "reboot"]
}
Response
{
  "success": true,
  "message": "Command queued successfully",
  "command_id": "cmd-uuid-here"
}
POSTDevice
Fetch pending commands
/device/commands-get/

The device calls this to check if any commands are waiting. All pending commands are returned and marked as "received" so they won't appear again on the next poll.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredYour device's ID
access_tokenstringRequiredToken from Device Verify
Response
{
  "success": true,
  "commands": [
    {
      "command_id": "cmd-uuid-here",
      "command": "reboot",
      "payload": { "delay_seconds": 5 }
    }
  ]
}
ⓘIf no commands are waiting, commands will be an empty list []. Poll this regularly to receive instructions in near real-time.
POSTDevice
Mark a command as completed
/device/commands-mark/

Once the device has finished executing a command, call this to confirm it's done. Only commands in "received" state can be marked complete.

Request Body
FieldTypeRequiredWhat it is
device_idstringRequiredYour device's ID
access_tokenstringRequiredToken from Device Verify
command_idstringRequiredID of the command that was executed
Example Request
{
  "device_id": "esp32-001",
  "access_token": "a3f9b2c1...",
  "command_id": "cmd-uuid-here"
}
Response
{ "success": true, "message": "Command marked completed" }
GETDashboard
Check the status of a command
/device/commands-status/<command_id>/

Look up the current status of any command by its ID. Useful from the dashboard to track whether a command has been picked up or completed.

URL Parameter
ParameterTypeWhat it is
command_idstringThe command ID passed directly in the URL path
Example
GET /device/commands-status/cmd-uuid-here/
Response
{
  "success": true,
  "command_id": "cmd-uuid-here",
  "command": "reboot",
  "status": "completed",
  "timestamp": "2025-06-11T10:32:00Z"
}
Possible Status Values
StatusMeaning
pendingQueued — device hasn't fetched it yet
receivedDevice fetched it — not yet executed
completedDevice confirmed it ran successfully
